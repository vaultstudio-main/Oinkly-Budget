# Oinkly Budget 1.0: release plan

Oinkly Budget 1.0 (build 5) is the first public release. Everything described in these documents is part of 1.0; there is no earlier version to compare it with. The original build that was first sent to App Review is kept as the tag `app-review-original-1.0` and the branch `legacy-1.0-original`. All work is on `main`.

The app is a full desktop program: no bank linking, no accounts, no network.

## What is built (all committed on `main`)

| Area | What it is | Status |
|---|---|---|
| Database | Schema V7 (V2 plus your reminders, saved CSV import formats, picture colours, the Month Outlook's closed-month figures and cash budget marks, which account a bill comes out of) with a safety copy of the data file before the first open (Application Support ▸ Backups), the data file pinned to where the app keeps it, and a one-time step that unpacks routing numbers and flags opening deposits | Done |
| Splits, recurring, tags | Split a payment across categories; repeating transactions that wait for you to confirm them; coloured tags shown in the register and managed in Settings | Done |
| Shortcuts and accessibility | Menu commands and shortcuts, VoiceOver labels, larger text | Done; the owner's own VoiceOver pass is still open |
| Export and import | Print PDF and Export CSV on every account and on the Transactions page, Export sheet (account, period, paper size), one transaction as a PDF, Import Statement on every account, default paper size and style in Settings | Done |
| Overview pages | Summary and Reports have no Print PDF button and no tag selector. Tags and PDFs belong to the transaction area | Decided 2026-10-21 |
| Widgets | Upcoming bills and reminders, with choices and a large size. No financial data, through an App Group snapshot | Done |
| Goals | Savings and debt payoff goals that follow an account; one goal section laid out the same on every account type | Done |
| Planning and reports | Budgets page, reports with six-month projections, Liabilities and Investments projections, Summary with priority bills | Done |
| Everyday | Clean Up (find and replace), payee autofill, locked opening deposits, separate wire and digital routing numbers, status colours, locked sidebar, bottom status bar | Done |
| Windows | Bigger Help and Release Notes windows | Done |
| Month Outlook | A page for what is left to save each month: income, bills and budgets, with bills linked to the payment that paid them, accounts and cash budgets you can leave out, and closed months kept | Done |
| Backup Copy and Sharing | Sealed file formats (.pigdata copies, .pig backups), a Backup Copy in a folder you choose, Sharing between Mac users, rescue screens, quiet start at login | Done; see `shadow-copy-plan.md` |
| Menu bar | Trimmed to Oinkly Budget, File, Transaction, Go and Help | Done |

Dropped: check printing (saved on the branch `check-printing`), attachments beyond receipt photos and PDF bills, encryption of the data file.

Every feature, how it works and its screenshots is in `feature-master-list-1.0.md`. Help, screenshots, website and release notes all follow it and are finished: `screenshot-plan.md`, `help-screenshots.md`, `release-notes-1.0.md`.

Data safety comes first: see `data-integrity-plan.md`. Nothing is submitted until every test in it passes on the release candidate.

## What is left

1. **Docs, Help, screenshots, website:** done and committed.
5. **Release notes** (written). Tell users about the Backups folder (the safety copy can be deleted later) and to make a `.pig` backup first.
6. **App Store text** (written; upload is the owner's).
7. **Export compliance.** The app has no encryption of its own, so `ITSAppUsesNonExemptEncryption` stays `false`.
8. **App Review notes.** Still no network, the data file stays on the Mac, widgets read local data only and show no financial data. The app has a narrow sandbox exception for the folder `/Users/Shared/OinklyBudget`, and asks for a folder the person picks (user-selected files plus a bookmark) for the optional Backup Copy, which may sit in iCloud Drive. Both are in `app-store-listing.md` and `app-review-reply.md`.
9. **Build and submit.** Version 1.0, build number up by one for every upload. The unused iCloud and push entitlements file is removed; the App Group entitlement stays for widgets. TestFlight, then submission or swap of build 5 in the review.

## Checks only the owner can do

Backup through the save panel, Import CSV on a real bank file, Print PDF in Preview (account pages), widgets and the menu bar pop-up, the locked sidebar in daily use, VoiceOver, the split, tag and recurring editors, a release build with the widget, and the Investments page on a real investment account.

## Risks

- **Migration:** an existing database that can't open is the worst outcome. Done and tested, with the safety copy as a backstop.
- **Scope:** keep it to the list above. Anything new goes after release.
- **Review:** keep release notes clear and the app free of crashes.

## Loose ends

- `docs/sample-bank-statement.csv`: keep or remove.
- The repository is one folder on `main`; the old nested repo is kept outside it as a backup.
- Menu bar app name: macOS builds it from the product name, and the owner said to leave it.

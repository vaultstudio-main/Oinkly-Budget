# Oinkly Budget 1.1: plan

**Status:** draft, for discussion. Nothing here is promised. It is where the plan for 1.1 is worked out in the open, and it will change as decisions are made.

**Where we are:** version 1.0.1 is out (1.0 build 6 plus the screen-size fix). 1.1 is the first release that is more than a bug fix: it should leave the app steadier than 1.0.1, and add one new feature people can see.

Updates come as time allows, with no fixed schedule. This plan is ordered by importance, not by date.

---

## Goals for 1.1

1. **Steadier.** Fix the known problems below, so that the app behaves on every screen and every test passes.
2. **One new feature,** chosen from the options below and done properly rather than several done halfway.
3. **Honest documentation.** Help, release notes and the website describe what the app really does now.

Not goals: bank linking, accounts or sign-in, any network use, or sync through a server. The app keeps your data on your Mac.

## 2. The new feature: options

Pick one. The recommendation comes first.

### Recommended: rules for payees ("auto-categorize")

When you type or import a payee, the app already remembers the last category and amount. A rule makes this deliberate and visible: "payee contains *Shell* is always *Gas & Fuel*". Rules run when transactions are added and when a CSV is imported, with a preview and Undo, as the importer already has.

- **Why:** it saves the most time for people who import statements, and it fits the app. It is local, reversible and needs no network.
- **Builds on:** Autofill, Clean Up and the CSV import preview.
- **Size:** medium. One new settings page, one small data type, hooks into add and import.
- **Risks:** a rule that is too broad. Mitigated by the preview, by showing which rule matched, and by Undo.

### Option B: search by tag, and saved searches

Carried over from the earlier 1.1 plan. Search the transactions by tag and save a search for reuse.

- **Why:** tags exist but are hard to use after the fact.
- **Size:** small to medium. Low risk.

### Option C: move your data between computers

Also from the earlier plan: a guided, automatic transfer of your data between two Macs, without a server, using the backup file or the backup-copy folder.

- **Why:** there is no sync on purpose, so moving to a new Mac relies on a backup file today.
- **Size:** large. The risk is high, because it touches the data file, so it needs the most testing.

### Option D: check printing

A branch, `check-printing`, was set aside from 1.0. It prints checks from a register.

- **Size:** medium. Useful to few people, and print layouts need careful testing.

### Option E: a yearly view

A year-at-a-glance page: each month's income, spending and kept amount in one grid, with a month-by-month budget comparison.

- **Why:** a natural next step from Reports and Budgets.
- **Size:** medium.

## 3. How 1.1 gets released

1. Fix everything under "Must fix". Ship nothing new until the data-safety tests pass.
2. Build the chosen feature behind a clear, reversible set of steps, and use the throwaway test data, never real data.
3. Test at four window sizes: 1280 × 800, 1512 × 982, 1728 × 1117 and 2560 × 1440.
4. Update Help, the in-app release notes, the README and the website.
5. Build, sign, notarize, make the `.dmg`, and publish it as a GitHub Release with a checksum.
